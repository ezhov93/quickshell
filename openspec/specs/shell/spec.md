## Purpose

Определить установленные возможности shell на Quickshell, их наблюдаемое поведение и общие правила shell рабочего окружения.

## Requirements

### Requirement: Entrypoint shell объединяет установленные модули
Entrypoint shell MUST объединять модули Bar, AppLauncher, Notifications, Wallpaper, Osd, MonitorManager и IdleInhibitor.

#### Scenario: Quickshell загружает entrypoint проекта
- **WHEN** загружается `shell.qml`
- **THEN** каждый установленный модуль создаётся внутри shell scope

### Requirement: Модули shell используют общие конфигурацию и тему проекта
Модули shell MUST использовать общие объекты конфигурации и темы для глобальных параметров, включая шрифт, команды, интервалы, пути, лимиты и цвета палитры.

#### Scenario: Модуль отображает UI проекта
- **WHEN** модуль показывает пользовательский элемент управления
- **THEN** он использует общую тему, а не определяет отдельную палитру проекта

### Requirement: Панель предоставляет состояние и управление рабочим столом
Панель MUST показывать рабочие пространства, активное окно, системный трей, состояние медиаплеера, громкость, яркость, информацию о ресурсах, сеть, доступную батарею, раскладку клавиатуры и время/дату на доступных экранах.

#### Scenario: Панель отображается в многомониторной сессии
- **WHEN** Quickshell сообщает доступные экраны
- **THEN** на каждом экране отображается экземпляр панели с актуальным состоянием рабочего стола и системы

### Requirement: Launcher поддерживает поиск и запуск с клавиатуры
Launcher MUST искать desktop-приложения по имени, общему имени, ключевым словам и категориям, а также поддерживать навигацию с клавиатуры, запуск по Enter/Return и закрытие по Escape.

#### Scenario: Пользователь ищет приложение
- **WHEN** пользователь вводит запрос и выбирает результат
- **THEN** отображаются подходящие приложения, а Enter/Return запускает выбранное приложение

### Requirement: Уведомления предоставляют ограниченную по объёму обратную связь
Сервис уведомлений MUST поддерживать содержимое, markup, изображения, actions, urgency, закрытие по timeout, явное закрытие и режим Do Not Disturb, отображая одновременно не более пяти уведомлений.

#### Scenario: Уведомление приходит при включённом Do Not Disturb
- **WHEN** сервис уведомлений получает уведомление
- **THEN** уведомление не отображается, пока Do Not Disturb включён

### Requirement: Shell предоставляет временные индикаторы громкости и яркости
OSD MUST показывать изменения громкости и яркости как временные индикаторы и MUST скрывать каждый индикатор после настроенного timeout.

#### Scenario: Изменяется громкость или яркость
- **WHEN** соответствующий общий сервис сообщает об изменении
- **THEN** соответствующий индикатор OSD становится видимым, а затем автоматически скрывается

### Requirement: Выбранные обои сохраняются
Возможность управления обоями MUST сканировать настроенные каталоги, поддерживать выбор и предпросмотр, применять выбранное изображение через настроенный backend обоев и сохранять успешно применённый путь для восстановления при следующем запуске shell.

#### Scenario: При запуске shell существует сохранённый wallpaper
- **WHEN** backend обоев становится доступен
- **THEN** shell пытается восстановить сохранённый wallpaper и сообщает об ошибке сохранения отдельно от ошибки применения

### Requirement: Изменения мониторов применяются и проверяются до сохранения
Возможность управления мониторами MUST получать состояние мониторов через Hyprland IPC, позволять изменять поддерживаемые свойства, применять изменения пакетом, проверять итоговое состояние и сохранять конфигурацию только после успешной проверки.

#### Scenario: Состояние монитора после применения не совпадает с запросом
- **WHEN** итоговое состояние отличается от запрошенного
- **THEN** изменение сообщается как ошибка и конфигурация не считается успешно сохранённой

### Requirement: Запрет бездействия действует только в рамках сессии
Idle inhibitor MUST использовать механизм Wayland idle-inhibit, предоставлять управление toggle/enable/disable через Quickshell IPC и запускаться выключенным после перезапуска shell.

#### Scenario: Пользователь включает запрет бездействия
- **WHEN** пользователь переключает или включает idle inhibitor
- **THEN** shell сохраняет поверхность inhibitor отображаемой, включает запрет бездействия и показывает временный индикатор состояния

### Requirement: Runtime shell не требует этапа сборки
Shell MUST запускаться непосредственно из QML-файлов и описателей модулей и MUST NOT требовать системы сборки или package manager приложения.

#### Scenario: Запускается установленная конфигурация
- **WHEN** Quickshell вызывается с путём к установленной конфигурации
- **THEN** QML shell загружается напрямую
