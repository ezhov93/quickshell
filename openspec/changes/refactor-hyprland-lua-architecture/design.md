## Context

Текущий `extra/hypr/hyprland.lua` — рабочий примерный профиль Hyprland 0.56.x и единственная точка загрузки. Он использует глобальный native Lua API `hl`, а порядок вызовов важен для окружения, автозапуска, настроек, правил и биндов. Цель рефакторинга — изменить организацию исходников, не меняя этот контракт.

## Goals / Non-Goals

**Goals:**

- Оставить основной путь загрузки `extra/hypr/hyprland.lua` неизменным.
- Разнести декларации по тематическим модулям с ясными границами ответственности.
- Сохранить единые значения `terminal`, `fileManager`, `browser`, `mainMod` и идентификатора `lpde-nmtui` без расхождений между модулями.
- Сделать порядок подключения явным и пригодным для статической проверки.
- Упростить локальный review diff при изменении одной группы настроек.

**Non-Goals:**

- Изменение пользовательского поведения, сочетаний клавиш или параметров Hyprland.
- Запуск, перезапуск или автоматическое применение графической сессии.
- Перенос `extra/hypr` в `configs/`, изменение `install.sh` или создание менеджера сессии.
- Добавление Lua-зависимостей, демонов или polling.

## Decisions

1. `hyprland.lua` остаётся тонким entrypoint и загружает модули в фиксированном порядке. Относительные пути вычисляются от расположения самого entrypoint, а не от текущего рабочего каталога Hyprland.
2. Модули размещаются в `extra/hypr/modules/` и используют общий контекст профиля. Контекст содержит общие команды и модификатор, чтобы не дублировать строки и не создавать разные значения биндов.
3. Группы файлов: `session.lua` (env и start), `settings.lua` (monitor/config/gesture), `applications.lua` (app commands), `windows.lua` (window rules), `keybinds.lua` (desktop/input), `media.lua` (volume/brightness/media), `shell.lua` (Quickshell IPC). Если выбранная версия Lua API не позволяет безопасно передать контекст, модуль может получать его единственным аргументом-функцией загрузчика; глобальный `hl` остаётся внешним API.
4. Не использовать `require` с неявным `package.path`, если это зависит от каталога запуска. Выбранный загрузчик должен явно выдавать ошибку при отсутствии или ошибке модуля.
5. Статическая проверка сравнивает список обязательных деклараций до и после разбиения: app-id `lpde-nmtui`, `main.pad` остаётся в QML-команде, `resize_on_border`, snap, keybinds, window rules и автозапуск должны присутствовать ровно один раз там, где это предусмотрено.

## Risks / Trade-offs

- [Ошибка порядка загрузки] → зафиксировать порядок в entrypoint и проверять загрузку профиля на целевой версии Hyprland без запуска пользовательской сессии.
- [Неизвестный текущий каталог при загрузке] → использовать путь, вычисленный из исходного файла, и статически проверить все ссылки на модули.
- [Расхождение общих значений между модулями] → передавать единый контекст и проверять дубликаты команд/идентификаторов.
- [Сложнее найти настройку в нескольких файлах] → имена файлов отражают ответственность, а документация содержит дерево и карту соответствий.

## Migration Plan

Сначала добавить модули и entrypoint-загрузчик, затем удалить дублированные декларации из старого файла после сравнения. Пользователь вручную копирует профиль и проверяет запуск, keybinds, автозапуск и окна. Откат — вернуть предыдущий единый `hyprland.lua`; новые модули не влияют на систему без подключения entrypoint.
