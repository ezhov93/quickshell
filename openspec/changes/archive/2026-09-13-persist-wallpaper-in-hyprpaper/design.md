## Context

Сервис обоев сейчас применяет путь через `hyprctl`, а затем записывает одну строку в `~/.config/quickshell/wallpaper.conf`. User-service `hyprpaper` читает другой файл — `~/.config/hypr/hyprpaper.conf` — поэтому выбранный путь не является источником его запуска. Текущий файл Hyprpaper также может содержать другие настройки и записи для мониторов, которые нельзя перезаписывать целиком.

## Goals / Non-Goals

**Goals:**

- Сохранять выбранный путь в формате, который читает `hyprpaper`.
- Обновлять только нужную wallpaper-запись, сохраняя остальные настройки.
- Использовать атомарную запись и различать ошибки применения и сохранения.
- Не читать и не изменять старый `~/.config/quickshell/wallpaper.conf`.

**Non-Goals:**

- Не менять жизненный цикл user-service `hyprpaper`.
- Не добавлять отдельный daemon или постоянный polling.
- Не редактировать конфигурации других мониторов без явной связи с выбранным монитором.
- Не удалять и не изменять старый `wallpaper.conf`, если он существует.

## Decisions

- `Config.qml` задаёт путь `~/.config/hypr/hyprpaper.conf` как persistent target. Поскольку текущий установщик управляет каталогом `~/.config/hypr`, он дополнительно переносит существующий `hyprpaper.conf` из backup в staged-конфигурацию при обновлении.
- Сервис получает текст существующего Hyprpaper-конфига, заменяет первый блок `wallpaper` или добавляет обычный блок, если его нет. Формат учитывает `monitor`, `path` и `fit_mode`; неизвестные строки сохраняются.
- Запись выполняется через существующий атомарный `TextFileWriter` после успешного ответа `hyprctl`. Ошибка применения не изменяет файл, ошибка записи не отменяет уже применённые обои.
- Старый `~/.config/quickshell/wallpaper.conf` не читается и не используется как источник состояния; единственным источником является `hyprpaper.conf`.
- Для восстановления используется конфигурация `hyprpaper`, а ограниченные попытки IPC остаются только для обновления текущего изображения после запуска Quickshell; запуск user-service остаётся ответственностью сессии.

## Risks / Trade-offs

- [Риск] Неполный парсер может повредить нестандартный Hyprpaper-конфиг → сохранять неизвестные строки, ограничить редактирование распознаваемыми блоками и выдавать ошибку до записи при неоднозначной структуре.
- [Риск] В конфиге могут быть записи для нескольких мониторов → выбирать монитор явно из доступного состояния, не удалять чужие блоки.
- [Риск] `hyprpaper` может не прочитать конфигурацию при ошибке запуска → диагностика остаётся в журнале user-service; Quickshell не дублирует startup IPC-команду.
- [Риск] Установка заменяет каталог Quickshell → основной файл находится в `~/.config/hypr`, поэтому обновление shell не удаляет состояние.

## Migration Plan

1. При запуске определить существующий первый блок `wallpaper` в `hyprpaper.conf`.
2. Записать обновлённый `hyprpaper.conf` атомарно.
3. При ошибке оставить старый файл без изменений и сообщить ошибку сохранения.

При обновлении через `install.sh` существующий `hyprpaper.conf` переносится из backup в новую конфигурацию; при отсутствии пользовательского файла используется поставляемый шаблон без конкретной обоины.

Откат реализации возвращает прежнюю логику чтения; новый `hyprpaper.conf` должен быть сохранён пользователем перед откатом.
