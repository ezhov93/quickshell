## Context

`extra/hypr/` содержит Lua-профиль Hyprland, hypridle, hyprlock, hyprpaper и monitor examples. Их перенос не должен означать автоматическую установку или подтверждённую переносимость.

## Goals / Non-Goals

**Goals:** определить владельца каждого файла, целевой путь, способ проверки и rollback.

**Non-Goals:** не менять содержимое конфигураций и не применять их в живой сессии.

## Инвентаризация

| Исходный файл | Назначение и зависимости | Целевой путь | Статус |
|---|---|---|---|
| `extra/hypr/hyprland.lua` | Основной профиль Hyprland; native Lua API `hl`, внешние команды Quickshell, hypridle, hyprpaper и polkit-agent | `configs/hypr/hyprland.lua` | Примерный session profile; отдельная session/deployment-проверка нужна |
| `extra/hypr/hypridle.conf` | Таймеры idle, `loginctl`, `hyprlock`, DPMS и suspend; зависит от hypridle и внешних команд | `configs/hypr/hypridle.conf` | Примерная idle-конфигурация; не systemd unit |
| `extra/hypr/hyprlock.conf` | Экран блокировки; зависит от hyprlock и PAM/аутентификации | `configs/hypr/hyprlock.conf` | Примерная lock-конфигурация; runtime проверяет владелец сессии |
| `extra/hypr/hyprpaper.conf` | Обои; зависит от hyprpaper и пользовательского пути обоев | `configs/hypr/hyprpaper.conf` | Примерная конфигурация, не универсальный deployment |
| `extra/hypr/monitors.conf` | Пример раскладки мониторов; зависит от конкретного оборудования | `configs/hypr/monitors.conf` | Пример/шаблон; не применять автоматически и не смешивать с runtime-generated settings |

Все пять файлов переносятся как конфигурационные примеры. Автоматическая установка, выбор пользовательских значений, systemd wiring и проверка полной сессии относятся к отдельным changes.

## Decisions

- Целевой слой — `configs/hypr/`; после этого change `extra/hypr/` больше не содержит переносимые конфигурационные файлы. Их примерный статус сохраняется документацией и отсутствием автоматического применения.
- Пути к домашнему каталогу, внешним командам и версиям фиксируются как ограничения, а не исправляются молча.
- Перенос проверяется сравнением содержимого, ссылок и `hyprland --verify-config` в контролируемой среде.

## Risks / Trade-offs

- [Риск] Перенос меняет ожидания запуска → [Митигация] не менять session profile автоматически и сохранить rollback.
- [Риск] Пример будет принят за универсальный → [Митигация] явно маркировать платформенные предположения.

## Migration Plan

Инвентаризация → согласование списка → перенос → проверка ссылок/содержимого → ручная проверка владельцем → обновление статуса.
