## MODIFIED Requirements

### Requirement: Entrypoint shell объединяет установленные модули

Полный состав оболочки MUST предоставлять панель, запуск приложений, уведомления, обои, OSD, управление дисплеями и запрет бездействия в рамках одной запущенной оболочки. Вспомогательные окна не обязаны открываться или создаваться заранее, пока пользователь их не вызвал.

#### Scenario: Quickshell загружает entrypoint проекта

- **WHEN** пользователь запускает полный состав оболочки в подготовленной сессии Hyprland
- **THEN** перечисленные возможности доступны через свои элементы управления или IPC, независимо от внутренней структуры классов и каталогов

### Requirement: Модули shell используют общие конфигурацию и тему проекта

Модули MUST использовать общие настройки шрифта, команд, интервалов, путей и лимитов, а также общую палитру проекта. Это не подразумевает существования графического редактора настроек или гарантии применения всех изменений без перезапуска.

#### Scenario: Модуль отображает UI проекта

- **WHEN** модуль создаёт визуальный элемент
- **THEN** элемент использует цвета и шрифт из общей темы и конфигурации, а не независимую палитру того же проекта

### Requirement: Панель предоставляет состояние и управление рабочим столом

Панель MUST отображаться на доступных экранах и предоставлять рабочие пространства, активное окно, трей, медиа, громкость, яркость, ресурсы, сеть, батарею при её наличии, раскладку и время. Неизвестные значения CPU и температуры MUST отображаться как `N/A`, а при отсутствии доступной батареи её индикатор MUST быть скрыт. Эти условия предполагают доступность обязательных QML-импортов.

#### Scenario: Панель отображается в многомониторной сессии

- **WHEN** оболочке доступны несколько экранов
- **THEN** на каждом доступном экране отображается панель

#### Scenario: Нет доступной батареи

- **WHEN** поставщик состояния батареи не предоставляет присутствующую батарею ноутбука
- **THEN** панель не показывает индикатор батареи с вымышленным зарядом

#### Scenario: Измерение ресурса недоступно

- **WHEN** значение CPU или температуры неизвестно
- **THEN** соответствующее значение отображается как `N/A`, а не как подтверждённый ноль

### Requirement: Launcher поддерживает поиск и запуск с клавиатуры

Запуск приложений MUST поддерживать поиск по имени, общему имени, ключевым словам и категориям desktop-приложений, навигацию с клавиатуры, запуск выбранного результата по Enter/Return и закрытие по Escape. Поиск MUST игнорировать регистр и внешние пробелы запроса.

#### Scenario: Пользователь ищет приложение

- **WHEN** запрос соответствует одному из поддерживаемых полей приложения
- **THEN** приложение присутствует в результатах поиска

#### Scenario: Пользователь запускает выбранное приложение

- **WHEN** в результатах выбрано приложение и пользователь нажимает Enter/Return
- **THEN** оболочка запрашивает запуск выбранного desktop-приложения

#### Scenario: Пользователь отменяет поиск

- **WHEN** открыто окно запуска приложений и пользователь нажимает Escape
- **THEN** окно закрывается без запуска приложения

### Requirement: Уведомления предоставляют ограниченную по объёму обратную связь

Оболочка MUST предоставлять уведомления с содержимым, изображениями, действиями, учётом срочности, ручным закрытием и режимом «Не беспокоить». Число одновременно удерживаемых уведомлений MUST ограничиваться настроенным пределом, равным пяти по умолчанию. Обычные уведомления MUST закрываться по таймеру, если указатель не находится над карточкой; критические не закрываются этим таймером. Оболочка MUST отображать разметку, поддержку которой заявляет сервер уведомлений. Последнее ограничение сохраняет ранее заявленный контракт; известное несоответствие реализации отмечается отдельно в статусе требований.

#### Scenario: Уведомление приходит при включённом Do Not Disturb

- **WHEN** включён режим «Не беспокоить» и приходит новое уведомление
- **THEN** оно не добавляется в отображаемый список; сценарий не обещает очередь отложенного показа или скрытие ранее показанных карточек

#### Scenario: Достигнут предел уведомлений

- **WHEN** добавление нового уведомления превышает настроенный предел
- **THEN** самое старое уведомление закрывается и число удерживаемых уведомлений не превышает предел

#### Scenario: Истекает таймер обычного уведомления

- **WHEN** уведомление не критическое, указатель не находится над карточкой и её таймер истекает
- **THEN** уведомление закрывается

#### Scenario: Пользователь выбирает действие уведомления

- **WHEN** пользователь нажимает доступное действие
- **THEN** оболочка вызывает соответствующее действие уведомления и удаляет его карточку

#### Scenario: Уведомление содержит поддерживаемую разметку

- **WHEN** тело уведомления содержит разметку, поддержку которой заявляет сервер
- **THEN** поддерживаемая разметка отображается как форматированный текст, а не буквальные теги

### Requirement: Shell предоставляет временные индикаторы громкости и яркости

При сообщении об изменении доступной громкости, состояния mute или яркости оболочка MUST показывать соответствующий OSD и скрывать его после периода без новых изменений. Текущий период составляет 1500 мс для каждого индикатора. Новое изменение MUST перезапускать период показа своего индикатора.

#### Scenario: Изменяется громкость или яркость

- **WHEN** соответствующий сервис сообщает изменение
- **THEN** появляется соответствующий индикатор и исчезает через 1500 мс без следующего изменения

### Requirement: Выбранные обои сохраняются

Оболочка MUST сканировать настроенные каталоги, предоставлять выбор и предпросмотр обоев, применять выбранное изображение через настроенный поставщик обоев и записывать путь только после успешного применения. При следующем запуске она MUST пытаться восстановить сохранённый путь с ограниченными повторными попытками. Ошибка применения и ошибка записи после успешного применения MUST различаться.

#### Scenario: Обои успешно применены

- **WHEN** внешняя команда применения завершилась успешно
- **THEN** выбранный путь становится текущим и оболочка запрашивает его сохранение

#### Scenario: Применить обои не удалось

- **WHEN** внешняя команда применения завершилась ошибкой
- **THEN** выбранный путь не записывается как успешно применённый, а ошибка доступна для диагностики

#### Scenario: Применение успешно, но запись не удалась

- **WHEN** запись пути завершается ошибкой после успешного применения
- **THEN** сообщается ошибка сохранения; уже применённое изображение не объявляется автоматически отменённым

#### Scenario: При запуске shell существует сохранённый wallpaper

- **WHEN** оболочка прочитала непустой сохранённый путь
- **THEN** первая попытка восстановления планируется через 1 секунду; после ошибки выполняются повторные попытки с интервалом таймера 1 секунда, всего не более десяти попыток
- **AND** после исчерпания попыток ошибка выводится в журнал; не обещается бесконечное ожидание готовности поставщика или восстановление за фиксированное общее время

### Requirement: Изменения мониторов применяются и проверяются до сохранения

Управление дисплеями MUST получать состояние через Hyprland IPC, позволять менять поддерживаемые параметры, применять запросы пакетом и выполнять новое чтение состояния после успешного ответа на применение. Запрошенная конфигурация MUST записываться только после успешной проверки результата. Проверка MUST NOT трактоваться как транзакционность пакета, доказательство визуальной пригодности изображения или автоматический откат.

#### Scenario: Все выбранные дисплеи выключены

- **WHEN** пользователь пытается применить черновик, в котором не остаётся включённых дисплеев
- **THEN** редактор сообщает ошибку и не отправляет этот запрос на применение

#### Scenario: Состояние монитора после применения не совпадает с запросом

- **WHEN** новое чтение состояния не соответствует запросу или завершается ошибкой
- **THEN** редактор сообщает ошибку и не записывает запрошенную конфигурацию

#### Scenario: Применение и проверка успешны

- **WHEN** новое чтение подтверждает запрошенные параметры
- **THEN** оболочка запрашивает сохранение конфигурации

#### Scenario: Сохранение после применения не удалось

- **WHEN** запись конфигурации завершается ошибкой после успешной проверки
- **THEN** редактор остаётся открытым и сообщает об ошибке записи, не объявляя применённое состояние автоматически отменённым

### Requirement: Запрет бездействия действует только в рамках сессии

Оболочка MUST предоставлять временный Wayland idle-inhibit через IPC `idle toggle`, `idle enable` и `idle disable`. После перезапуска оболочки режим MUST быть выключен. Механизм запрашивает запрет бездействия, а не отключение явной блокировки пользователем или гарантию предотвращения любого системного перехода в сон.

#### Scenario: Пользователь включает запрет бездействия

- **WHEN** режим включается через элемент управления или IPC
- **THEN** активируется Wayland idle-inhibit для отображаемой поверхности и показывается временный индикатор изменения состояния

#### Scenario: Оболочка перезапускается

- **WHEN** запускается новый экземпляр оболочки после завершения предыдущего
- **THEN** запрет бездействия не восстанавливается автоматически

### Requirement: Runtime shell не требует этапа сборки

Поставляемая оболочка MUST запускаться установленным Quickshell непосредственно из QML-файлов и описателей модулей без сборки собственного кода перед запуском. Это ограничение не запрещает будущие инструменты разработки и тестирования и не относится к сборке внешнего Quickshell дистрибутивом.

#### Scenario: Запускается установленная конфигурация

- **WHEN** Quickshell вызывается с путём к установленной конфигурации и необходимые импорты доступны
- **THEN** оболочка загружается из поставленных QML-файлов без отдельного шага сборки проекта
