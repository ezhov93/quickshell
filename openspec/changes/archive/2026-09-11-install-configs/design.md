## Context

`install.sh` сейчас атомарно заменяет только `~/.config/quickshell`, а `configs/hypr/` не разворачивает. Конфигурационный слой должен попадать в пользовательский `~/.config/`, но нельзя резервировать или заменять весь этот каталог: там находятся независимые настройки пользователя.

## Goals / Non-Goals

**Goals:**

- Разворачивать весь текущий каталог `configs/` по схеме `configs/<path>` → `~/.config/<path>`.
- Сохранить существующую безопасную staging/backup модель для shell и расширить её на управляемые config-пути.
- Сделать результат повторяемым и диагностируемым без запуска приложений.
- Подготовить откат при ошибке до завершения установки.

**Non-Goals:**

- Установка пакетов, systemd units, portals или Hyprland.
- Автоматический `hyprctl reload`, запуск Quickshell или изменение live session.
- Слияние пользовательских конфигураций строка-в-строку.
- Backup всего `~/.config` или перенос runtime state вроде `wallpaper.conf` и generated monitor settings.

## Decisions

1. Источником становится каталог `configs/` рядом с `shell/`. Установщик рекурсивно копирует его обычные файлы в `~/.config/`, сохраняя относительные пути; отсутствие каталога считается ошибкой валидации источника.
2. Shell и configs устанавливаются как единый staged deployment, но имеют независимые управляемые цели: `~/.config/quickshell` и каждая верхнеуровневая подпапка `~/.config/<configs-child>`. Это позволяет резервировать `~/.config/hypr`, не затрагивая `~/.config/foot`, `~/.config/gtk-3.0` и другие пути.
3. Перед установкой все существующие управляемые цели перемещаются в один backup-каталог с поддеревьями `quickshell/` и config paths. При ошибке staging/установки cleanup восстанавливает цели; при успехе backup остаётся и печатается пользователю.
4. Установщик не применяет конфигурацию. После завершения он сообщает установленные пути и отдельную ручную команду, например `hyprctl reload`; саму команду агент и installer не выполняют.
5. Файлы из `configs/` копируются как есть. Валидация проверяет наличие, относительные пути и отсутствие runtime state в источнике; адаптация домашнего пути, platform-specific package names и пользовательское слияние — отдельные задачи.

## Risks / Trade-offs

- [Риск] Конфигурация пользователя будет заменена → [Митигация] backup только управляемых подпапок и восстановление при ошибке.
- [Риск] Частичный сбой оставит shell и configs в разных версиях → [Митигация] общий staging и rollback всех ещё не подтверждённых перемещений.
- [Риск] Установка будет принята за применение сессии → [Митигация] явное сообщение, отсутствие reload/exec и ручной checklist владельца.
- [Риск] В `configs/` попадёт пользовательское состояние → [Митигация] source allowlist/валидация и отдельный запрет generated/runtime-файлов.

## Migration Plan

Обновить проверки источников → подготовить staged копии shell и configs → создать backup управляемых целей → установить каталоги → вывести пути и команды ручного применения → проверить rollback в отдельной тестовой среде. Откат выполняется восстановлением backup; живой `~/.config/hypr` агентом не изменяется в ходе проверки.
