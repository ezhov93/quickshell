## Context

См. мотивацию в `proposal.md`. Репозиторный профиль сейчас находится в `extra/hypr/hyprland.conf` и не устанавливается `install.sh`. Пользовательский референс `/home/ezhov/.config/hypr/hyprland.lua` использует API `hl.*`, задаёт Hyprland 0.56.x и содержит поведение, которое не совпадает с действующим профилем: другие gaps/rounding, дополнительные настройки и жесты, другой Chromium command, переменные курсора вместо трёх текущих переменных окружения, отключённые группы, конфликт `Super+Shift+S`, отсутствие `Super+Shift+E` и дополнительные команды/window rules.

Hyprland 0.56.2 подтверждает native Lua manager через `hyprland --verify-config --config <file>.lua`; отдельной команды `hl` нет. Точный пользовательский путь остаётся ответственностью профиля сессии и не устанавливается проектом автоматически.

Ключевые расхождения и принятые решения:

| Область | Референс | Итоговый профиль |
|---|---|---|
| Автозапуск | Только Quickshell | Quickshell, polkit-agent, hypridle и hyprpaper |
| Окружение | `XCURSOR_SIZE`, `HYPRCURSOR_SIZE` | Три session-переменные плюс обе переменные курсора |
| Оформление | gaps 4/6, rounding 4 | Сохраняются текущие обязательные gaps 3/5 и rounding 5; добавлены совместимые opacity/layout параметры |
| Браузер | Chromium с Wayland/VA-API флагами | Перенесён как в референсе |
| Группы | Helper `hl.dsp.window.group` отсутствует | Не переносятся |
| Screenshot/scratchpad | Screenshot и scratchpad используют `Super+Shift+S` | Scratchpad не переносится; `PRINT` сохраняет PNG, `Super+Shift+S` копирует screenshot в буфер |
| Сессия | Нет `Super+Shift+E` | `Super+Shift+M` запускает `uwsm stop` |
| Window rules | Два правила | Перенесены оба правила |
| Отложенные IPC | `Super+N` и `Super+C` в текущем change не согласованы | Hotkey удалены; необходимость `dismiss_all` и `idle toggle` выносится в отдельную будущую capability |

## Goals / Non-Goals

**Goals:**

- Сделать Lua-профиль проекта каноническим примерным входом для поддержанного загрузчика из референса.
- Сохранить обязательный контракт `session`, если отдельное решение пользователя не расширит scope.
- Перенести дополнительные рабочие настройки референса только после проверки их API, команд и конфликтов.
- Оставить профиль примерным и отдельно проверять его в контролируемой Hyprland-сессии.

**Non-Goals:**

- Не внедрять новый daemon, polling, IPC-адаптер или менеджер lifecycle.
- Не расширять `install.sh`, не устанавливать пакеты и не настраивать UWSM автоматически.
- Не объявлять Arch и Debian совместимыми без отдельных проверок.
- Не менять `hypridle.conf`, `hyprlock.conf`, `hyprpaper.conf` и `monitors.conf`, если это не требуется доказанным способом подключения профиля.
- Не принимать все отличия референса как желаемое поведение без фиксации решения по конфликтам.

## Decisions

### Каноническое имя и подключение определить по реальному загрузчику

Сначала нужно проверить, какой компонент предоставляет `hl` и как он подключает `/home/ezhov/.config/hypr/hyprland.lua`. Новый файл в `extra/hypr/` должен использовать тот же формат и точку входа; нельзя выдавать Lua-файл за нативно загружаемый Hyprland без подтверждения. Старый `.conf` удаляется или оставляется только как явно неканоничный legacy-файл согласно результату проверки загрузчика.

Альтернатива — вручную переписать Lua в нативный `.conf` — отвергнута: она не выполняет запрос пользователя. Альтернатива — добавить собственный Lua-рантайм в проект — отвергнута как новая зависимость и отдельная архитектурная задача.

### Нормативная спека важнее неполного референса

Референс используется как источник дополнительных настроек, но обязательные текущие декларации сохраняются: в частности, автозапуск `polkit`, `hypridle`, `hyprpaper` и три session environment variables. Если API референса не поддерживает конкретную декларацию напрямую, задача должна либо найти эквивалентный механизм, либо остановиться с описанием конфликта.

### Конфликт `Super+Shift+S` решён в пользу двух screenshot-режимов

В текущем `.conf` `Super+Shift+S` перемещает окно в scratchpad, а в референсе делает screenshot с `wl-copy`. По решению пользователя scratchpad полностью исключён, а оба screenshot-режима сохранены: `PRINT` сохраняет PNG, `Super+Shift+S` копирует снимок в буфер.

### Проверять конфигурацию послойно

Статически сопоставляются исходный `.conf`, референс и итоговый Lua: monitor, env, autostart, input, appearance, workspace, keybinds и window rules. Затем выполняется проверка загрузчика/`--help` и, только если доступна отдельная безопасная сессия, runtime-проверка запуска, IPC, раскладок и keybinds. Единственная живая сессия не используется для lock/exit/restart экспериментов.

### Владельцу окружения принадлежит графическая проверка

Агент выполняет статические проверки, но не поднимает и не изменяет графическую сессию. Проверки загрузки, внешнего вида, раскладок, keybinds, автозапуска и Wayland-интеграций выполняются пользователем вручную по checklist из `docs/testing.md` в подготовленной сессии с recovery-путём. До получения такого результата задача остаётся незавершённой, а отсутствие runtime-свидетельства не трактуется как успех.

### Не добавлять стоимость выполнения

Lua-профиль остаётся конфигурацией, а не новым процессом. Единственные внешние процессы — уже объявленные команды сессии и команды, вызванные keybinds; новые процессы не добавляются без отдельного обоснования.

### Отложить спорные IPC-функции отдельным change

По решению пользователя текущий профиль не назначает `Super+N` для `notifications dismiss_all` и `Super+C` для `idle toggle`. Модули и прямые IPC targets сохраняются, чтобы отдельный будущий change мог сначала определить необходимость, UX, сочетания и критерии проверки; удаление модулей сейчас создало бы более широкий scope.

Функциональная проверка DND и MonitorManager также не входит в закрытие этого change. В текущем change подтверждается только то, что Lua-профиль регистрирует и вызывает активные IPC-команды: `Super+Shift+N` для DND и `Super+O`/`Super+Shift+O` для мониторов. Корректность поведения самих модулей выносится в отдельные задачи; открытие окна MonitorManager без рабочей обработки не считается исправлением этой функции.

## Risks / Trade-offs

- [API `hl` может быть пользовательским расширением, отсутствующим на целевой системе] → Зафиксировать поставщик, версию и команду запуска; при отсутствии оставить runtime-задачу заблокированной и не заявлять готовый deployment.
- [Референс меняет существующее поведение] → Составить таблицу расхождений и сохранить нормативные требования до отдельного согласования.
- [Конфликт keybinds может скрыто зависеть от порядка регистрации] → Запретить дубли и проверить итоговую карту сочетаний.
- [Удаление `.conf` сломает текущий способ запуска] → Сначала подтвердить новый loader и план отката; не удалять legacy-файл до доказанного подключения.
- [Запуск exit/lock в живой сессии опасен] → Выполнять только в подготовленном recovery-окружении; иначе отметить runtime как заблокированный.

## Migration Plan

1. Зафиксировать загрузчик `hl`, версии и целевой путь Lua-профиля.
2. Составить таблицу различий `.conf` ↔ референс и утвердить решения по конфликтам.
3. Добавить Lua-профиль, сохранить обязательные декларации и провести статические проверки.
4. Проверить подключение в контролируемой сессии; только после этого изменить роль/наличие старого `.conf`.
5. При откате вернуть `.conf` как основной вход и удалить/отключить Lua-профиль; пользовательская конфигурация не изменяется автоматически.
