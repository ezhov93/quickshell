## Context

Сейчас `shell/config/Config.qml` запускает сетевые настройки командой `foot -e nmtui`. Все такие окна имеют общий app-id Foot, поэтому правило по классу `foot` затронуло бы и обычные терминалы. `extra/hypr/hyprland.lua` уже содержит window rules в native Lua API Hyprland 0.56.x. По документации Hyprland статический эффект `float` должен находиться вне `match` и надёжно сопоставляться с начальным классом окна.

## Goals / Non-Goals

**Goals:**

- Сделать окно `nmtui`, запущенное из панели, плавающим.
- Ограничить правило конкретным экземпляром Foot через отдельный app-id.
- Разрешить изменение размера окон перетаскиванием за границу.
- Включить недорогое событийное прилипание только для floating-окон.
- Сохранить текущий запуск `nmtui` и поведение обычных окон Foot, включая их глобальный внутренний отступ.

**Non-Goals:**

- Выбор универсального терминала или применение change `design-default-applications`.
- Назначение размера, позиции, workspace или pin для окна.
- Автоматическая установка Foot, NetworkManager либо Hyprland-профиля.
- Запуск или перезапуск графической сессии агентом.

## Decisions

1. `Config.networkSettingsCommand` получает вид `['foot', '--app-id=lpde-nmtui', '-o', 'main.pad=0x0', '-e', 'nmtui']`. Foot устанавливает app-id до создания Wayland-окна, а `-o` локально переопределяет `main.pad` только для этого запуска; статическое правило Hyprland может сопоставить окно при открытии.
2. В `extra/hypr/hyprland.lua` добавляется именованное правило с `match.class = '^lpde-nmtui$'` и эффектом `float = true`. Размер и центрирование не задаются, поскольку пользователь запросил только floating-режим.
3. В `general` включается `resize_on_border = true`, как в end-4. Это глобальная настройка взаимодействия с границей; она не задаёт начальный размер окна.
4. В `general.snap` применяются значения end-4: `enabled = true`, `window_gap = 4`, `monitor_gap = 5`, `respect_gaps = true`. `border_overlap` не задаётся и остаётся выключенным по умолчанию. Snap работает при перемещении и изменении размера floating-окон, не добавляет polling или отдельный процесс.
5. Матчинг по title не используется: заголовок TUI может измениться после создания окна, а статические эффекты Hyprland оцениваются при открытии. Матчинг по общему классу `foot` отклонён, потому что изменил бы все терминалы.
6. Статическая проверка включает наличие одинакового app-id в QML-команде и Lua-правиле, локального `main.pad=0x0` и сохранение отсутствия override для обычного Foot. Runtime проверяет владелец сессии: открывает `nmtui`, сверяет `class` через `hyprctl clients`, отсутствие внутренних полей, меняет размер за границу, проверяет прилипание, затем открывает обычный Foot и сравнивает режимы и отступ.

## Risks / Trade-offs

- [Примерный Hyprland-профиль не установлен] → правило не влияет на активную пользовательскую конфигурацию; пользователь применяет его вручную.
- [Версия Foot не поддерживает `--app-id`] → запуск завершается ошибкой; в текущем окружении опция подтверждается локальным `foot --help`.
- [Версия Foot не поддерживает `-o/--override`] → локальное отключение отступа не применится; в текущем окружении опция подтверждается локальным `foot --help`.
- [Lua API Hyprland изменится] → перед применением профиль проверяется на целевой версии 0.56.x, а графический runtime остаётся ручной проверкой.
- [Глобальные resize и snap меняют взаимодействие со всеми floating-окнами] → используются небольшие пороги end-4; начальные размеры, позиции и перекрытие границ не включаются.

## Migration Plan

Изменить команду и примерный Lua-профиль, выполнить статические проверки, затем передать пользователю ручной checklist. Откат состоит в удалении `--app-id=lpde-nmtui`, `-o main.pad=0x0`, соответствующего window rule, возврате `resize_on_border = false` и удалении блока `snap`; данные пользователя не мигрируются.
