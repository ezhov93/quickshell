## Context

См. мотивацию в `proposal.md`. Сейчас `NetworkWidget` является `BarButton`, а `NetworkService.openSettings()` запускает команду из `Config.networkSettingsCommand`, которая открывает `foot -e nmtui`. `NetworkService` уже получает устройства и сети через `Quickshell.Networking`: Wi‑Fi устройство предоставляет модель `networks`, а сеть имеет `name`, `known`, `connected`, `signalStrength`, `security`, `connect()`, `connectWithPsk()` и `disconnect()`.

Целевое устройство ограничено по CPU и памяти. Сканирование Wi‑Fi нельзя оставлять постоянно активным: оно должно включаться только при открытом popover и отключаться после закрытия.

## Goals / Non-Goals

**Goals:**

- Заменить обычный запуск `nmtui` на компактный popover, визуально привязанный к сетевому индикатору панели.
- Разделить UI на состояние Wi‑Fi, сохранённые сети, сворачиваемый раздел других сетей, модальный ввод пароля и расширенный fallback.
- Сохранить системные операции подключения в `NetworkService`, а пароль, выбранную сеть и открытый раздел — в UI.
- Поддержать клавиатуру, Escape, клик снаружи, видимый focus и сообщения о переходном/ошибочном состоянии.
- Использовать текущую тему, шрифт и Quickshell Networking без нового процесса или демона.

**Non-Goals:**

- Не реализовывать полноценный менеджер всех профилей NetworkManager.
- Не добавлять управление Ethernet, VPN, Enterprise Wi‑Fi или редактирование профилей; для них остаётся `nmtui`.
- Не добавлять ручной ввод SSID и подключение к скрытым сетям.
- Не хранить пароль в конфигурации проекта, файле или долгоживущем singleton-состоянии.
- Не выполнять постоянный polling или фоновое сканирование после закрытия popover.
- Не менять внешний контракт других сетевых иконок панели и fallback-команду без необходимости.

## Decisions

### 1. Popover принадлежит NetworkWidget

Сетевой popover создаётся рядом с `NetworkWidget` и открывается по клику/клавиатурной активации. Это сохраняет пространственную связь с источником действия и не требует отдельного полноэкранного `PanelWindow`. Закрытие выполняется по Escape, клику вне popover или после успешного подключения, если это не мешает отображению ошибки.

Альтернатива — отдельное полноэкранное layer-shell окно — даёт больше контроля над modal-фокусом, но добавляет поверхность, геометрию и риск пустых слоёв для небольшого меню.

### 2. Четыре визуальные секции и модальный пароль

Внутри popover идут: переключатель Wi‑Fi; «Сохранённые сети»; сворачиваемые «Другие сети»; «Другие настройки». Список сохранённых и других сетей строится из одного поставщика, разделение выполняется по `known`. Текущая сеть визуально отмечается независимо от того, к какому разделу она относится. Выбор новой PSK-сети открывает отдельный модальный диалог над содержимым popover, блокирующий действия с фоновым списком до подтверждения или отмены.

Секции и строки остаются отдельными компонентами только там, где есть собственное состояние или повторное использование: `NetworkPopover`, `NetworkSection`, `NetworkRow` и `NetworkPasswordDialog` либо эквивалентная меньшая граница после проверки QML-дерева. Декоративные заголовки не выделяются в отдельные типы.

### 3. Сканирование управляется жизненным циклом popover

При открытии popover включается `WifiDevice.scannerEnabled` на доступном Wi‑Fi устройстве. Модель NetworkManager автоматически обновляет раздел «Другие сети» по мере получения результатов. При закрытии scanner выключается, если до открытия не был включён внешним потребителем.

Если активного Wi‑Fi устройства нет, UI показывает безопасное состояние вместо обращения к отсутствующей модели. Кнопка ручного обновления и интервал polling не добавляются: обновления приходят из модели NetworkManager только при открытом popover.

### 4. Подключение использует возможности Network API

Для известной сети вызывается `connect()`. Для неизвестной открытой сети также выполняется подключение без секрета. Для неизвестной PSK-сети пароль остаётся локальным состоянием диалога и передаётся только в `connectWithPsk()` после подтверждения. Состояния `stateChanging`, `connected` и `connectionFailed` используются для блокировки повторной операции и диагностики.

Типы Enterprise/EAP, VPN и неизвестные методы аутентификации не имитируются как PSK. Для них popover показывает, что операция не поддерживается, и предлагает пункт `nmtui`.

### 5. Wi‑Fi toggle остаётся системной операцией

Переключатель меняет `Networking.wifiEnabled`, а UI показывает аппаратно недоступное состояние отдельно от программно выключенного Wi‑Fi. NetworkService предоставляет узкую операцию/свойство для popover вместо копирования доступа к native API в компоненты.

### 6. Расширенный fallback сохраняется

`Config.networkSettingsCommand` остаётся источником команды `nmtui`, но `NetworkWidget` больше не запускает её напрямую при обычном клике. Пункт fallback вызывает существующую операцию `NetworkService.openSettings()`. После перехода правило Hyprland для app-id `lpde-nmtui` не требуется для popover; его можно сохранить для ручного запуска, пока отдельная cleanup-задача не подтвердит безопасное удаление.

## Risks / Trade-offs

- [Риск сканирования продолжит работать после закрытия] → сохранить исходное значение `scannerEnabled`, выключать только собственное включение и проверить закрытие/повторное открытие.
- [Риск пароль останется в состоянии после смены сети] → очищать пароль при закрытии, успешном подключении и ошибке; не передавать его в логи.
- [Риск API NetworkManager не предоставляет сеть до включения scanner] → показывать loading/empty/error отдельно и проверить Wi‑Fi устройство в runtime.
- [Риск popover обрежется у края экрана] → использовать якорь окна панели и корректировку размещения; проверить правый край и узкую геометрию.
- [Риск Enterprise-сеть будет выглядеть подключаемой] → явно различать поддерживаемые PSK/open типы и fallback на `nmtui`.
- [Риск добавление компонентов повысит стоимость QML-дерева] → загружать popover лениво и не создавать его, пока он закрыт.

## Migration Plan

1. Расширить `NetworkService` узкими операциями Wi‑Fi и жизненным циклом сканирования, не меняя текущий статус Ethernet.
2. Добавить popover и строки сетей, подключить его к `NetworkWidget`, зарегистрировать внутренние типы.
3. Перевести обычный клик на popover, а `nmtui` оставить отдельным пунктом fallback.
4. Обновить Config/Hyprland-документацию, checklist и статус требований; удалять floating-правило только после отдельной проверки ручного fallback.
5. Проверить rollback возвратом старого вызова `openSettings()` и соответствующих QML-компонентов одной ревизией Git.
