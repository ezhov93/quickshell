## 1. Контракт и исследование

- [ ] 1.1 Сверить требования capability с существующими XDG desktop/MIME механизмами и session environment на Arch/Debian; зафиксировать совместимые и неподдерживаемые случаи.
- [ ] 1.2 Зафиксировать первую роль `terminal` и документированный приоритет пользовательской настройки, environment и fallback; проверить, что XDG оставлен расширением для будущих графических ролей.

## 2. Архитектура разрешения

- [ ] 2.1 Спроектировать границу resolver/service и структурированный argv-контракт для графических приложений и TUI-команд; проверить отсутствие зависимости UI от конкретного бинарника.
- [ ] 2.2 Спроектировать диагностику источника, недоступной команды и ошибки запуска; проверить, что resolver не добавляет daemon, polling или обязательный пакет.

## 3. Проверка и интеграция

- [ ] 3.1 Подготовить тестовые сценарии для явной настройки, environment fallback, отсутствующего приложения и запуска TUI-команды в `foot`; проверить сценарии в изолированной среде.
- [ ] 3.2 После отдельного решения о применении перевести сетевые настройки на resolver без изменения наблюдаемого запуска `foot -e nmtui`; проверить ручным вызовом в пользовательской сессии.
- [ ] 3.3 Обновить документацию зависимостей и статус требований, указав ограничения Arch/Debian и не заявляя непроверенную переносимость; проверить ссылки и OpenSpec validation.
