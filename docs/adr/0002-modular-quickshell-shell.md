# ADR-0002: Модульная оболочка в одном процессе Quickshell

- Статус: принято для новых изменений; соответствие старого кода неполное
- Дата: 2026-09-10

## Контекст

Целевое оборудование ограничено по CPU и памяти. Текущий `shell.qml` уже объединяет модули и общие singleton-сервисы в одном процессе Quickshell. При этом исходный архитектурный контекст ошибочно показывал зависимость компонентов от модулей и предполагал отдельный адаптер для каждой интеграции.

## Решение

Полный состав оболочки по умолчанию работает в одном процессе Quickshell:

```text
shell.qml
    |
    v
 modules --------> components
    |
    v
 services -------> native APIs or justified adapters
```

Стрелка означает «использует».

- Модуль объединяет пользовательский сценарий, визуальные компоненты и сервисы.
- Визуальный компонент хранит состояние представления и сообщает о действиях, но не владеет общим системным состоянием и не запускает системные операции.
- Сервис предоставляет состояние возможности и операции над ним.
- Сервис может использовать штатный API Quickshell напрямую.
- Адаптер создаётся только при собственной ответственности: сложном протоколе, преобразовании, повторном использовании или необходимости подмены в проверках.
- Отдельный процесс добавляется только после архитектурного обоснования.

## Рассмотренные альтернативы

- Процесс на каждую возможность: повышает изоляцию, но добавляет память, запуск и координацию; текущим требованиям не нужен.
- Обязательный слой адаптера для каждого API: формально симметричен, но создаёт пустые обёртки.
- Прямой доступ любого UI к системе: уменьшает число файлов, но смешивает представление, состояние и ошибки и усложняет проверку.

## Последствия

- Общие QML-сервисы не называются демонами.
- Новый код следует направлению зависимостей; перенос старого кода выполняется отдельными изменениями.
- `modules/Bar/components/WorkspaceList.qml` пока напрямую использует Hyprland и отмечен как G01 в карте статуса.
- Это решение не выбирает UWSM, systemd-схему сессии или новую структуру runtime-каталогов.
- Ошибка одного обязательного QML-импорта всё ещё может помешать загрузке процесса; деградация возможностей должна проектироваться явно.
