# Архитектура LPDE

Этот документ описывает текущее устройство проекта и правила его развития. Нормативное поведение находится в [OpenSpec](../openspec/specs/), а степень соответствия реализации — в [карте статуса](spec-status.md).

Метки документа:

- **Существует** — подтверждено исходниками или конфигурацией.
- **Ограничение** — принятое правило для новых изменений; старый код может ещё ему не соответствовать.
- **Будущий этап** — направление, для которого нужен отдельный OpenSpec change.

## 1. Текущая структура

| Путь | Состояние и ответственность |
|---|---|
| `shell/shell.qml`, `shell/qmldir` | **Существует.** Точка композиции полного состава оболочки и корневой manifest модуля `qs`. |
| `shell/modules/` | **Существует.** Пользовательские возможности: Bar, AppLauncher, Notifications, Wallpaper, Osd, MonitorManager и IdleInhibitor. Внутри модуля UI находится в `components/`, а относящиеся к возможности состояние и логика — в `services/`. |
| `shell/components/` | **Существует.** Общие визуальные примитивы оболочки. |
| `shell/services/` | **Существует.** Общие QML-сервисы одного процесса Quickshell: аудио, яркость, файловые операции и Hyprland IPC. Это не каталог отдельных демонов. |
| `shell/config/` | **Существует.** Общая тема и настройки оболочки, импортируемые как `qs.config`. |
| `configs/hypr/` | **Существует.** Примерный Lua-профиль Hyprland (`hyprland.lua`), hypridle, hyprlock, hyprpaper и monitor profile. Текущий установщик его не разворачивает. |
| `install.sh` | **Существует.** Устанавливает только QML и `qmldir` в `~/.config/quickshell`. |
| `openspec/` | **Существует.** Основные требования и изменения в работе. |
| `docs/` | **Существует.** Контекст, архитектура, решения, статус требований, тестирование и рабочие инструкции. |

| `configs/` | **Существует.** Конфигурации Hyprland и будущие конфигурации приложений/пользовательские шаблоны. Перенесённый профиль остаётся примерным и не устанавливается автоматически. |
| `packages/` | **Будущий этап.** Package manifests и различия Arch/Debian; текущий снимок пакетов остаётся в `extra/`. |
| `system/` | **Будущий этап.** systemd user units, portals и session wiring; сейчас таких собственных деклараций нет. |
| `services/` | **Будущий этап.** Собственные внешние сервисы/демоны проекта после отдельного архитектурного обоснования. Это не `shell/services/`. |
| `install/` | **Будущий этап.** Deployment-профили и данные установки; текущий совместимый entrypoint остаётся в корневом `install.sh`. |
| `scripts/` | **Существует.** Разработческие и проверочные скрипты, не являющиеся runtime-зависимостью shell. |
| `extra/` | **Переходная область.** Снимок пакетов и материалы, ещё не отнесённые к продуктовому слою; перенесённые конфигурации Hyprland здесь не дублируются. |
| `quickshell.code-workspace` | **Существует.** Editor metadata Git-корня; не является частью runtime и не устанавливается в `~/.config/quickshell`. |

Будущие каталоги создаются только вместе с первым ответственным файлом или отдельным change. Наличие каталога само по себе не подтверждает реализацию соответствующего слоя.

## 2. Процессы

**Существует:** полный состав QML объединяется одним `Scope` в одном экземпляре Quickshell. QML-сервисы являются singleton-объектами внутри этого процесса. Hyprland, PipeWire/WirePlumber, NetworkManager, UPower, hyprpaper и другие платформенные службы — внешние процессы.

Проект не запрещает пользователю вручную запустить второй экземпляр Quickshell и пока не предоставляет собственного менеджера жизненного цикла сессии.

**Ограничение:** новый самостоятельный процесс допускается только при ответственности, которую нельзя разумно выполнить конфигурацией, внешним сервисом или объектом внутри Quickshell. До реализации определяются владелец запуска, остановка, привилегии, сбои и стоимость ресурсов.

**Будущий этап:** определить одного владельца запуска компонентов сессии, порядок готовности, перезапуск оболочки и очистку процессов при выходе. systemd user units и UWSM являются вариантами, а не принятыми зависимостями.

## 3. Направление зависимостей

Стрелка означает «использует»:

```text
shell.qml
    |
    v
 modules --------> components
    |
    v
 services
    |
    +------------> native Quickshell APIs
    |
    +------------> adapters, when they have a responsibility
                         |
                         v
                  external APIs / IPC
```

Обновления возвращаются к UI через свойства, сигналы и QML bindings.

**Ограничения:**

- Переиспользуемый визуальный компонент не зависит от использующего его модуля.
- Сервис не зависит от визуального компонента.
- Визуальный примитив не запускает системный процесс и не владеет общим состоянием системы.
- Отдельный адаптер вводится для сложного протокола, преобразования, повторного использования или заменяемости в проверках. Готовый API Quickshell можно использовать непосредственно из сервиса.

Известное отклонение: `shell/modules/Bar/components/WorkspaceList.qml` напрямую использует Hyprland. Оно учтено как G01 в [карте статуса](spec-status.md#g01-прямая-системная-зависимость-ui).

Верхнеуровневые зависимости направлены от deployment к описаниям среды и runtime: `install/` может использовать `packages/`, `system/` и `configs/`, а они могут описывать запуск `shell/`. `shell/` не импортирует package manager, installer или system units. `scripts/` проверяет слои, но не является runtime-зависимостью.

## 4. Состояние и UI

Локальное состояние представления может жить в UI: наведение, фокус, открытость окна, выбранная строка и ещё не применённый черновик. Например, редактор дисплеев хранит отдельный черновик и только после действия пользователя передаёт его сервису.

Подтверждённое состояние внешней системы и операции над ним принадлежат сервису. После операции UI не должен выдавать желаемое значение за фактическое без ответа или повторного чтения поставщика.

Термины, которые нужно различать в новых интеграциях:

- **желаемое состояние** — запрос пользователя;
- **фактическое состояние** — последнее подтверждённое значение поставщика;
- **операция выполняется** — изменение ещё не подтверждено;
- **ошибка** — запрос, чтение или сохранение не выполнены;
- **недоступно** — устройство или поставщик отсутствует.

Общая обязательная модель свойств для всех старых сервисов пока не введена.

## 5. Настройки и сохраняемые данные

**Существует:** `shell/config/Theme.qml` и `shell/config/Config.qml` поставляются вместе с QML. Выбор обоев сохраняется в `~/.config/quickshell/wallpaper.conf`. Менеджер дисплеев может записывать `~/.config/hypr/monitors.conf` или `monitors.lua`, если основной конфигурационный файл подключает его.

Текущий установщик заменяет каталог `~/.config/quickshell` целиком после создания backup и не переносит `wallpaper.conf` в новую установку. Это ограничение G02, а не обещание сохранения пользовательского состояния при обновлении.

**Будущий этап:** классифицировать пользовательские настройки, долговременное состояние, кэш и runtime-файлы по XDG-каталогам и определить миграцию. До этого пути в коде остаются текущим фактом.

## 6. Интеграции и сбои

| Возможность | Текущая граница | Обновление | Известные ошибки/ограничения |
|---|---|---|---|
| Аудио | `services/Audio.qml`, Quickshell PipeWire | События свойств | Нет sink — `available=false`; отдельного адаптера нет. |
| Яркость | sysfs для чтения, `brightnessctl` для записи | FileView и опрос 2 с | sysfs не гарантирует события; отсутствие устройства даёт `available=false`; ошибка команды пишется в журнал. |
| CPU, память, температура | `/proc` и `/sys` | Опрос только при видимой панели: CPU/память 2 с, температура 5 с | Неизвестные CPU/температура отображаются как `N/A`. |
| Сеть | Quickshell Networking; `ip -j route` как fallback | События API; fallback 15 с только при видимой панели и отсутствии управляемого подключения | Ошибка fallback даёт неизвестное/недоступное состояние. |
| Батарея | Quickshell UPower | События свойств | При отсутствии батареи индикатор скрыт. |
| Уведомления | Quickshell NotificationServer | События уведомлений и таймеры | Сервер заявляет markup, карточка выводит plain text — G08. |
| Обои | сканирование каталогов, `hyprctl hyprpaper` | По запросу; восстановление до 10 попыток по 1 с | Ошибка применения отделена от ошибки записи; готовность поставщика не отслеживается событием. |
| Дисплеи | сокет Hyprland через `services/HyprlandClient.qml` | События Hyprland и опрос 3 с только при открытом редакторе | После применения состояние перечитывается; транзакционность и визуально безопасный автоматический откат не обеспечены. |

**Ограничение:** новые интеграции описывают успешный путь, отсутствие поставщика, ошибку операции, внешнее изменение и восстановление, если оно поддерживается. Нельзя приписывать старому сервису обработку, которой в нём нет.

## 7. Установка

`install.sh`:

1. отклоняет запуск от root;
2. предупреждает об отсутствующих командах, но не устанавливает пакеты;
3. создаёт staging-каталог;
4. проверяет и копирует только `shell/shell.qml`, `shell/qmldir`, `shell/config/`, `shell/components/`, `shell/services/` и `shell/modules/`, сохраняя их относительные пути;
5. перемещает прежний `~/.config/quickshell` в backup;
6. ставит новый каталог и печатает команду запуска.

Установщик не проверяет версии, QML-импорты и шрифт, не запускает оболочку, не меняет Hyprland и не включает службы. Runtime allowlist не захватывает документацию, OpenSpec, `extra/` и editor metadata. `extra/packages-2026-09-09.txt` — снимок явно установленных пакетов одной машины, не воспроизводимый манифест.

## 8. Сессия

Пример `configs/hypr/hyprland.lua` использует встроенный Lua API Hyprland 0.56.x и задаёт окружение, ввод, лёгкое оформление, keybinds и однократный запуск `quickshell`, polkit-agent, hypridle и hyprpaper. `configs/hypr/hypridle.conf` декларирует блокировку через 300 с, DPMS off через 600 с и suspend через 1200 с.

Это не менеджер сессии и не проверка выполнения. Lua-профиль требует Hyprland с native Lua manager и доступные внешние команды; фактический запуск компонентов, переносимость, готовность, перезапуск, завершение и блокировка требуют отдельных проверок. Установщик оболочки эти файлы не применяет.

## 9. Ресурсная модель

Текущая оболочка избегает постоянной работы там, где это уже предусмотрено: ресурсные и сетевые fallback-опросы связаны с видимостью панели, редактор дисплеев опрашивает состояние только открытым, а launcher, wallpaper и monitor manager создают окна лениво.

Опрос яркости продолжает работать при скрытом OSD, потому что сервис должен обнаружить внешнее изменение и показать индикатор. Это обоснованный активный потребитель, а не исключение без причины.

**Ограничение:** для нового polling указываются поставщик, отсутствие надёжного события, интервал, потребители и условие остановки. Новый фоновый процесс требует отдельного обоснования.

**Будущий этап:** определить воспроизводимую методику измерения idle CPU, памяти, числа процессов, частоты пробуждений и времени запуска на целевом оборудовании. До измерений численные бюджеты не считаются принятыми.
